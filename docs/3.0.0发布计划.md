## 0. 定位说明（先读）

当前代码**已是** `versionName 3.0.0` / `versionCode 3000000`。2.x 阶段功能（v2.0 → v2.4.0）已全部收敛；随后完成的 **Apple 风格 UI 重设计** 与 **A/B/C/E/F/G 六项候选功能**在 `CHANGELOG.md` 中被记为「3.x 大版本基线确立」。

**结论：3.0.0 目前只是一个「大版本号」，尚未承载与之匹配的大版本内容。** 本计划给出可作为 3.0.0 **正式发布**内容的功能更新与重大改动方向。

> ⚠️ 口径待裁决：若你的本意是「把刚完成的重设计 + 六功能视为 2.x 收尾，另起一轮 3.0.0」，本计划可整体平移，仅版本号口径需调整。

**两条必须先解决的文档冲突（见 §6）：**
1. `PRD.md §9` 把 `v3.0.0` 定义为 M4「架构演进（可选）」（`PRD.md:788`：**播放状态机收敛 / `SongItem` 补 `year`、播放模式类型统一 / 控制器接口化+无设备单测 / 细粒度状态更新**），而**实际发布的 3.0.0 是「大版本基线 + UI 重设计 + 6 功能」**，二者主题不一致。
2. `PRD.md §9` 的 M1~M3（`v2.3.1 / v2.4.0 / v2.5.0`）**从未单独发布**（CHANGELOG 中确无 v2.3.1 / v2.5.0），代码直接 2.4.0 → 3.0.0；且 M3「多端扩展」实际在 3.0.0 周期内才完成。**里程碑编号与真实版本序列已错位。**

## 2. 发布主题

以 `CHANGELOG.md:11` 确立的定位为准 —— **「本地离线、隐私最小权限；聚焦内容组织与体验纵深」**，3.0.0 正式发布收敛为三条主线：

1. **平台基线现代化** —— 把 API 24 双分支兼容层收敛到单一 API 26 路径。
2. **数据与性能架构演进** —— 数据层从 blob 存储升级为关系型；大列表虚拟化；内存治理。
3. **内容组织与体验纵深** —— 音效、搜索增强、卡片、i18n、标签编辑等面向真实使用深度的功能补齐。

#### A1. 平台基线升级：compatibleSdkVersion 24 → 26 🔴
- **核心内容**：抬高最低 API 到 26，**删除全部 API 24 降级垫片**——`common/utils/ApiCompat.ets` 闸门、`SheetMaterial.ets` 的 `import type` + 运行期动态 `import()`、`MusicInfoComponent.ets` 的 ContainerReader 降级分支、`Layout.ets` / `SongDetailSheet.ets` 的内联动态 import、`fill` 重载降级；同步消除 **14 条 @since WARN**（沙箱无法构建核对，须真机确认）。
- **预期价值**：代码路径单分支化、维护成本减半、解锁 API 26 全量能力（uiMaterial 全风格、ContainerReader 容器断点、新 media API）。
- **影响模块**：`build-profile.json5`、`common/utils/ApiCompat.ets`、`common/utils/SheetMaterial.ets`、`pages/Layout.ets`、`components/SongDetailSheet.ets`、`components/MusicInfoComponent.ets`，以及 **9 个持有 `@State material` 的调用方**（AddToPlaylistSheet:44 / ControlAreaComponent:89 / OnboardingSheet:39 / AlbumDetail:60 / About:44 / ArtistDetail:60 / Settings:65 / PlaylistDetail:66 / **SongDetailSheet:78**）。

#### A2. 数据层重构：MusicStore 由 Preferences 升级为 RDB 🔴
- **核心内容**：`services/MusicStore.ets` 现以 `Preferences` 存 JSON 大 blob（每次写 `JSON.stringify(this.songs) + flush()` 全量重写；`getPlaylistSongs:148` 为 `filter+includes` 的 O(n·m)；`getAllArtists/getAllAlbums:377-396` 每次调用重建 Set+sort）。迁移到 `relationalStore`（RDB）：songs / favorites / recently_played / playlists / play_counts / play_ms 建表 + 索引，改为增量 SQL 读写。
- **预期价值**：大曲库性能与内存显著改善，消除全量重写，支撑搜索/排序/分页（B2 的前置），为曲库规模增长铺路。
- **影响模块**：`services/MusicStore.ets`、所有读写方（`AudioRendererController`、Playlists / PlaylistDetail / Favorites / PlayHistory / DuplicateSongs / Wrapped、`SmartPlaylistService`）、设置迁移。
- **迁移注意**：需一次性数据迁移（首启读旧 Preferences JSON → 写入 RDB → 成功后标记），带 `db_version` schema 版本化与失败回滚策略；`SettingsStore`（独库 `app_settings`）是否一并迁移见 §7 OQ-2。

#### A3. 大列表虚拟化：落地 LazyForEach + IDataSource

### P1 · 核心功能更新

#### B1. 音效与均衡器（补齐播放器能力）
- **核心内容**：当前**零音效**（无 AudioEffect/Equalizer/BassBoost/淡入淡出/crossfade/空间音频）。接入系统音效能力：多段 EQ、淡入淡出、crossfade；空间音频视权限可得性决定。
- **预期价值**：补齐「音乐播放器」核心能力，形成差异化。

- **预期价值**：直接兑现「内容组织」主题，大曲库可用性。
- **影响模块**：`pages/LocalLibrary.ets`、（可选）新增 Search 路由、`services/MusicStore.ets`、`common/utils/SortUtil.ets`。
