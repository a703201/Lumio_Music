## 1. 缺陷根因与修复闭环判定

原缺陷：`WidgetCard.ets` 声明了 `@LocalStorageProp('isDark')`（现 `WidgetCard.ets:67`），取色逻辑完整，但**没有任何写入方**——`FormAbility.onAddForm` 与 `AVSessionController.pushFormUpdate` 的 `createFormBindingData` 均不含 `isDark`，导致卡片恒为浅色。

修复后写入方（两路，均已核实覆盖）：

| 路径 | 触发时机 | 位置 | 判定 |
|---|---|---|---|
| 首帧同步写入 | 卡片创建 `onAddForm` | `FormAbility.ets:78-85`（含 `isDark`） | ✅ |
| 运行期主动推送 | 播控/主题变化 + 播放中每 1s | `AVSessionController.ets:699-708`（含 `isDark`） | ✅ |
| 主题切换主动推送 | `setThemeMode` / `refreshSystemTheme` | `ThemeManager.ets:108,121` → `pushCardThemeUpdate()` | ✅ |

**闭环成立**：浅色/深色/跟随系统三种用户，在「卡片新建」「主应用播放」「手动切主题」「系统深浅色切换」四个触发点均有写入，缺陷 1 已真正修复。`form_config.json:16` `updateEnabled:false`（无定时刷新）恰好印证：主应用主动推送是**唯一**更新路径，`refreshSystemTheme` 的补推送是必需而非可选。

## 2. 逐文件结论

### 2.1 `entry/src/main/ets/common/utils/ThemeResolver.ets`（新增）— ✅ 通过

- 零依赖纯函数（不引用 window/AppStorage/Preferences/Logger），Form 进程与主应用均可安全调用，达成「单一判定源、消除双份漂移」的设计目标。
- 三种模式判定：`light→false`、`dark→true`、`system→systemIsDark`，语义正确（详见 §4 D-13）。
- `import type { ThemeMode } from '../../utils/SettingsStore'`（L19）：type-only import 编译期擦除，**不会**把 SettingsStore 及其依赖（MusicStore/AVSessionController）拖进卡片侧模块图，路径正确。
- 无 `any`/`unknown`/解构/对象字面量类型；Apache-2.0 头完整。

### 2.2 `entry/src/main/ets/utils/PreferencesUtil.ets`（新增 `getThemeModeSync`）— ✅ 通过

- `getThemeModeSync()`（L191-205）：`preferences.getPreferencesSync` + `pref.getSync` 同步读盘，**@since 10**，API 24 可用（官方文档已核实，见 §3 B-7）。
- **显式指定库名 `'app_settings'` 正确且必要**：`app_settings` / `theme_mode` 与 `SettingsStore.ets:35`（`PREF_NAME='app_settings'`）、`:38`（`KEY_THEME_MODE='theme_mode'`）**逐字一致**；若沿用默认 `myStore` 则恒读默认值 —— 开发者说明属实。
- 失败/非法值回落 `'system'` 并记日志（L200-204），符合容错要求；内部无 `await`，适配 `onAddForm` 同步签名。
- 无裸 `console.*`/`hilog`（走 `Logger`）。
- **⚠️ P2-①**：`APP_SETTINGS_STORE`/`THEME_MODE`（L49-50）为「显式镜像」常量，与 `SettingsStore` 双份定义。注释已承认该风险，但长期存在漂移隐患。

### 2.3 `entry/src/main/ets/formability/FormAbility.ets`（`onAddForm` 下发 `isDark`）— ✅ 通过（含 1 项 P2）

- `onAddForm` 保持**同步签名**：内部无 `await`；`readSystemIsDark()`（L54-61）与 `getThemeModeSync()` 均为同步；`addFormId()`（L75）为 fire-and-forget 异步，未阻塞返回值。L78 同步 `return formBindingData.createFormBindingData(...)`。✅
- `this.context.config.colorMode`（L56）：**在 FormExtensionContext 上有效**（官方 FormExtensionContext 文档示例即使用 `this.context.config.language`；`Context.config: Configuration` 自 API 9 起可用，`Configuration.colorMode` 即系统深浅色）。**无需 `canIUse` 守卫**。✅
- `readSystemIsDark()` 失败回落浅色并记日志，与 `ThemeManager` 兜底策略一致；系统色深为 `NOT_SET` 时 `!== COLOR_MODE_DARK` → 返回 false（浅色），行为合理。✅
- `createFormBindingData` 字段名与 `WidgetCard` 的 `@LocalStorageProp` 逐一对应（详见 §4 D-12）。✅
- **⚠️ P2-②**：Form 进程内 `preferences` 存在**进程级实例缓存**。若卡片进程长期存活、期间主应用改了 `theme_mode` 又再次 `onAddForm`，`getThemeModeSync` 可能读到本进程缓存的旧值。影响极小（下一次 `pushFormUpdate` 会自愈覆盖），记录备查。

### 2.4 `entry/src/main/ets/utils/AVSessionController.ets`（`pushFormUpdate` 携带 `isDark`）— ✅ 通过

- **D-16 关键结论**：新增的 `isDark` 取值是 `AppStorage.get('isDark')`（**L691**）——**内存读取，非磁盘 I/O**。team-lead 最担心的「每秒一次磁盘 I/O」**不成立**（详见 §4 D-16）。
- L699-708 `createFormBindingData` 8 个字段（title/artist/album/duration/position/lyric/isPlaying/isDark）与卡片 8 个 `@LocalStorageProp` 完全对应。
- 全程 `.catch` 兜底（L709、L714），无未捕获 rejection。
- L688-690 的 TODO 差分守卫取舍说明清晰、判断合理（播放中 position 每秒变化，差分无效），未擅自改动已稳定逻辑。

### 2.5 `entry/src/main/ets/utils/ThemeManager.ets`（`isDark` 委托 + 主题切换补推送）— ✅ 通过（含 2 项 P2）

- `isDark()`（L79-84）委托 `resolveIsDark()`，与卡片侧同源，达成防漂移目标。✅
- `setThemeMode()`（L108）/`refreshSystemTheme()`（L121）末尾各调一次 `pushCardThemeUpdate()`；`pushCardThemeUpdate()`（L129-135）`try/catch` **仅记日志、不 rethrow**，不会打断主题切换主流程。✅
- `refreshSystemTheme()` 注释（L112-117）正确指出它是「跟随系统」用户的主路径，设计判断准确。✅
- **⚠️ P2-③（语义等价性唯一疑点）**：类头注释（L28）称旧实现「`isDark()` 读取 ApplicationContext 的 ColorMode」，现改为读 `AppStorage('systemIsDark')`；而 `systemIsDark` **仅**在 `EntryAbility.onConfigurationUpdated`（`EntryAbility.ets:420-421`）写入。`ThemeManager.init()` 在 `onWindowStageCreate`（`EntryAbility.ets:327`）调用，若冷启动时 `onConfigurationUpdated` 尚未触发，「跟随系统」用户首帧可能误判为浅色，直到首次配置回调到达才修正。**建议**：在 `init()` 内先用 `context.config.colorMode` 主动初始化一次 `systemIsDark`，或确认该回调在 `onWindowStageCreate` 前必定触发后补注释说明。
- **⚠️ P2-④**：`pushCardThemeUpdate()` → `AVSessionController.getInstance()`（L131）。若切主题发生于 AVSession 尚未创建时（冷启动后未播放即切主题），`getInstance()` 会**构造** `AVSessionController` 并触发 `initAVSession()`（异步 `createAVSession/activate`），属副作用扩张。**建议**：提供 `getExistingInstance()` 或仅当 `AppStorage` 中已存在实例时才推送。

### 2.6 `entry/src/main/ets/widget/pages/WidgetCard.ets`（旁涉改动，见 §5 范围）

磁盘当前版本已改用 `tokens/LumioColor` 的 `semanticOf()` + `CARD_CONTROL_BG_*` 常量，**消除了早期版本的硬编码 hex**（`#1C1C1E`/`#F2F2F7` 等）。`semanticOf` 所在 `LumioColor.ets` 经确认为**零 import** 模块（L20 注释声明 + grep 无 `^import`），Form 卡片进程引用安全。✅
