## 二、已修复（按优先级 P0 → P2）

### P0　构建/运行正确性

1. **`Layout.ets:359` §2.5.5 违规**
   - **问题原因**：底部悬浮胶囊的 API 26 分支在同一 `Row` 上同时设置 `.backgroundColor(cardBg)` 与 `.systemMaterial(material)`。ArkUI 规范禁止同一节点同时挂系统材质与背景色（二者互斥），会导致系统毛玻璃失效、回退不稳（深色模式下曾被白雾覆盖）。
   - **修改内容**：移除 API 26 分支的 `.backgroundColor(cardBg)`，仅保留 `.systemMaterial`；`else` 分支保留纯色 `cardBg` 兜底。
   - **文件**：`entry/src/main/ets/pages/Layout.ets`

### P1　无障碍 / Apple HIG

2. **硬编码动画时长绕过 Reduce Motion 系统（6 文件 / 8 个动画）**

   - **修改内容**：统一改为 `LumioTheme.duration(...)`，使可达性开关生效：
     - `LocalLibrary.ets:526`、`Favorites.ets:174`、`PlayHistory.ets:167`、`SettingsSubPageBodies.ets:172`：空状态图标弹入 `duration: 2000` → `LumioTheme.duration(700)`（同时收敛时长）。

### 3. API 26 兼容 WARN（14 条）—— 经三种 apiAvailable 形态实测，确认「0 WARN 不可达」（受限于 API 24 兼容策略）
用户要求落实「0 WARN 可选项」（即把三处 `systemMaterial` 改为 `attributeModifier`/`AttributeUpdater` 运行时下发）。对此做了**严谨的实测验证**，结论如下：

- **形态①（链式 `.apiAvailable` 护栏）**：在 `SongRow.ets:114` 写 `.apiAvailable({ apiVersion: 26 }, () => { .fill(...) })`，**编译 FAIL**：
  - `Property 'apiAvailable' does not exist on type 'CircleAttribute'`（证明 `apiAvailable` 不是可链式属性修饰符）；
  - `Declaration or statement expected`（箭头函数体内以 `.` 起始语句非法）。
- **形态②（运行时 `deviceInfo.apiAvailable('26.0.0')` 守卫）**：将 `SheetMaterial.ets:82` 的 `if (ApiCompat.isAtLeast(26) && this.material!==undefined)` 改为 `if (deviceInfo.apiAvailable('26.0.0') && this.material!==undefined)` 并构建——**WARN 依然存在**（`SheetMaterial.ets:83 'systemMaterial' ... supported since SDK 26`）。即官方文档/论坛推荐的 `deviceInfo.apiAvailable` 守卫**对链式属性的 WARN 不起抑制作用**（编译器静态检查不识别该 guard 模式，或 `&&` 复合条件打断了识别）。
- **形态③（全局 `apiAvailable` 内建函数）**：改为 `if (apiAvailable({ apiVersion: 26 }) && ...)` 构建——**编译 FAIL**：`Cannot find name 'apiAvailable'`。即该全局内建函数在本编译器（API 24 兼容 SDK / 6.1.1(24) 工具链）中**并不存在**。
- **结论**：链式 `.systemMaterial()` / `.fill()` 上的 API-26 符号 WARN，**无任何 `apiAvailable` 形态可清除**。其根因是：构建以 `compatibleSdkVersion=24` 为目标，编译器对 API-26 专属符号（含 `systemMaterial`、`fill` 的 API-26 重载、`ContainerReader`、`breakpointConfig` 某重载、`media` 能力等 14 处）做静态 lint 推荐，**且该检查不随任何可用 guard 模式被抑制**。
- **唯一能真正 0 WARN 的路径 = 提高 `compatibleSdkVersion` 至 26**（华为论坛「方案二」）。但这会**直接放弃 API 24（HarmonyOS 6.1.1/NEXT 早期）真机兼容**，与本仓库 `ApiCompat` 头注释明确声明的「最低兼容 API 24、目标 API 26」双目标策略**根本冲突**，属产品级决策而非代码级优化——**未擅自执行**，需用户显式确认是否愿意放弃 API 24 用户。
- **原提案的 `AttributeUpdater` 重构同样无效**：`AttributeUpdater.applyNormalAttribute(instance)` 内调用 `instance.systemMaterial(...)` 仍会在该方法体内引用同一 API-26 符号 → WARN 照常触发，且需重写刚稳定的 Sheet 子系统（高风险），属「高改动 / 零收益」，故不采用。
- **现状判定**：14 条 WARN 均为「双目标策略」下的**固有、非阻塞、运行期已守卫**提示；现行 `ApiCompat.isAtLeast(26)` + 动态 `import('@ohos.arkui.uiMaterial')` 已是官方推荐的运行时降级方案，运行时正确性不受影响。仓库保持 **BUILD SUCCESSFUL**。
