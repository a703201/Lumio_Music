# P0 复验清单 · 播放页叠封面元素（浅色主题 + 深色封面）

> 对应提交：`b7a07de`（P0 修复）、`dbfc957`（媒体层令牌化）、`9a7c968`（引导页响应式）
> 目的：真机确认媒体层令牌维度正确、无"浅色主题下播放页控件不可见"的回归。

---

## 0. 为什么必须验这一场景

| 事实 | 含义 |
|---|---|
| 播放页背景**恒压暗**（`PlayerInfoComponent` 蒙层 + `setOrCreate('lyricBgDark', true)`，与主题无关） | 叠在封面上的控件/文字**两种主题下都应是浅色（白）** |
| 本轮将叠封面元素从硬编码 `Color.White` 改为 `onMediaOf(true)`（媒体层令牌） | 若误传**应用主题**标志给 `onMediaOf`，浅色主题下会取到深色 → 落在压暗背景上不可见 |
| 该错误已在 `b7a07de` 修复 | **浅色主题 + 深色封面 = 旧缺陷暴露场景**，优先级最高 |

**一句话判据**：不管主题是浅是深，播放页上的控件与文字都应当是**浅色、清晰可见**的。若在浅色主题下看到深色图标/深色文字 → P0 未修净。

## 3. 歌词对比度复验（R-24：必须截图取样，不能只看色值）

> 理论色值会**高估**实际对比度（blur 削平细笔画峰值亮度），故必须真机取样。

- [ ] **播放态**非当前行：对比度 **≥ 3:1**
- [ ] **浏览态**（拖拽歌词、或手动滚动后 2s 内）全部行：**≥ 4.5:1**
- [ ] 当前行清晰、与其它行有明确层次
- [ ] 取样方法：截图 → 取「文字像素色」与「其背景像素色」→ 计算对比度（取色器/公式）

---

## 4. 主题切换响应性（不重启 App）

- [ ] 停在**播放页**切主题（浅 → 深 → 浅）：控件/文字颜色**立即正确**，无需退出重进
- [ ] 打开**首次引导**页后切主题：4 个特性图标的底色（accent / warning / purple / success）应随主题刷新（`9a7c968` 修复点；重点看 warning 橙与 success 绿）
