## 2. 架构与边界决策

- **C++ ↔ ArkTS 职责边界（明确）**：C++ `parseAudioMetadata` 仅作 MediaKit 失败/字段缺失时的**文本元数据兜底**（title/artist/album/duration/sr/channels）；封面/内嵌歌词仍由 ArkTS 层负责，避免重复解析与 I/O 浪费。
- **拖拽重排数据流**：`PlaylistDetail` 手势 → 解析 `onDrop` extraParams（dragIndex/insertIndex）→ `MusicStore.reorderPlaylistSongs`（权威 `songIds` 数组 splice + 持久化）→ 页面按 `songIds` 顺序重渲染。不引入新存储。

## 3. 实施结果（已实现，待审查）

- **A**：`MusicStore.reorderPlaylistSongs(playlistId, from, to)`；`PlaylistDetail` 列表项 `.onDragStart` 记录起点、`.onDrop` 调用重排；加「长按歌曲可拖动排序」提示。
- **B**：`Playlists.ets` 空状态呼吸动画由 `setInterval` 改为 `UIContext.animateTo` 循环（列表非空自动停止、无定时器残留）。

- **E**：`Find.ets` 已删除；`main_pages.json` 仅注册 `pages/Index`，无构建影响。
