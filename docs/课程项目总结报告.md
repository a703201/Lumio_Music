## 一、项目概述

Lumio Music 是一款运行于 **HarmonyOS 6.1.1（API 24）** 平台的纯本地音乐播放器，基于 **ArkTS + ArkUI + C++ NAPI** 开发。无需账号体系、无需网络、无需第三方 API，用户通过系统文件选择器导入本地音频后即可完全离线使用。

**核心数据**：
- 14 个页面、24 个一级功能模块
- 34 个功能需求（FR-01 ~ FR-34），全部已实现
- C++ 原生音频元数据解析器（FLAC / MP3 / MP4）
- 6 轮迭代，累计修复 P0×6 / P1×10 / P2×12
- HarmonyOS 静态审查：**0 ERROR / 0 WARNING**
- 45 条单元测试，核心逻辑语句覆盖率 >70%

## 二、功能清单

### 基础播放
- 播放 / 暂停 / 上一首 / 下一首
- 播放模式切换（顺序 / 列表循环 / 单曲循环 / 随机）
- 进度条拖拽、播放时间显示
- 后台播放（`KEEP_BACKGROUND_RUNNING` 权限 + AVSession 媒体会话）
- 锁屏媒体控制、桌面音乐卡片

### 音乐库
- 系统文件选择器导入本地音频（MP3 / FLAC / M4A / WAV）
- 搜索过滤、播放中高亮
- 空状态呼吸动画引导导入
- 错误态 + 重试按钮（store 初始化失败 / 导入失败）
- 音频元数据自动读取（标题 / 艺术家 / 专辑 / 年代）

### 收藏与历史
- 收藏 / 取消收藏
- 最近播放（最多 50 条，自动去重置顶）
- 清空播放历史

### 自建歌单
- 新建 / 重命名 / 删除歌单（同名校验）
- 歌单内添加 / 移除歌曲
- 长按拖拽排序（`ForEach.onMove`，持久化保存）
- 播放全部（将歌单曲目设为播放队列）

### 播放器页面
- 封面大图（内嵌封面自动抽取 + 缓存）
- 一镜到底共享元素动画（迷你播放器 ↔ 播放器页面）
- Canvas 歌词显示（LRC / KRC 格式，原文 + 翻译自动识别）
- 歌词手动滑动浏览（滑动取消模糊，5 秒自动回正）

### 交互体验
- 长按选项栏（替代右侧「更多」按钮，覆盖 5 个页面）
- 歌曲详情半模态面板（文件名 / 标题 / 歌手 / 年代 / 添加时间）
- 添加到歌单半模态面板（支持面板内新建歌单）
- HDS 设计系统、沉浸光感、智感握姿自适应

### 设置
- 设置子页分类（自动下一首 / 播放模式 / 主题 / 锁屏控制）
- 主题切换（系统 / 浅色 / 深色）
- 关于页（版本号运行时读取 `bundleManager`）
- 隐私政策页

## 六、AI 协作模式

本项目采用 **「主理人 + 9 角色专家团」** 模型进行 AI 辅助开发：

- **工作流**：需求 → pm-planner 规划 → code-developer 实现 → code-reviewer 审查 → 文档回写
- **核心原则**：AI 负责"可离线验证的逻辑"，人工负责"需系统上下文感知的判断"
- **审查机制**：每轮改动都经过 `harmonyos-reviewer` 静态扫描（API 合规、版本兼容、权限声明）
- **5 轮审查**：初版 P0×6 P1×10 → 二轮 P2×12 → 三轮 NFR → 四轮细节 → 五轮测试，全部闭环为 0 ERROR / 0 WARNING

## 八、关键踩坑与收获

1. **ArkTS 编译器红线**（7 条）——解构声明、`any` 类型、`get` 访问器在 `@Component` 上被丢弃等，全部规避
2. **`bindSheet` 多绑定覆盖**——ArkUI 同一组件只能挂一个，后挂覆盖先挂
3. **构建环境陷阱**——`genie-safe-delete.cjs` 拦截 hvigor 清理产物导致随机崩溃，`build_hap.sh` 脚本彻底解决
4. **C++ taskpool 闭包陷阱**——`new taskpool.Task(()=>{})` 在真机静默抛 10200014，必须用顶层 `@Concurrent` 具名函数
5. **ID3v2 UTF-16BE 无 BOM**——中文乱码根因是未按大端解析，补 `isBE = (enc == 2)` 后修复
