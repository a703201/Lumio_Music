## 修复：本地音乐播放器无法播放（HM_Player / Lumio Music）
- **根因**：`AudioRendererController.loadAndPlay()` 只设置 `avPlayer.fdSrc`（→initialized 状态），但从未调用 `prepare()`，也没有任何地方在 prepared 后触发 `play()`。AVPlayer 状态机要求 idle→initialized→prepared→playing，缺中间两步导致永远停在 initialized，UI 第二次点击 `start()` 时 `play()` 在非法状态被拒绝 → 无声。
- **修复（官方推荐模式）**：在 `stateChange` 回调中驱动状态机 —— `initialized`→`prepare()`，`prepared`→`start()`(即 play())。同时修复文件句柄泄漏：新增 `curFile` 字段，切歌/释放时 `closeSync`。

## 第十二轮：运行期崩溃 Cannot read property bg of undefined（@Component 普通 getter 被丢弃）

背景：第十二轮诊断确认「投播内容受版权加密保护」提示与播控失效无关（投播/播控解耦）。本轮按 pm-planner+system-architect+code-reviewer 定稿方案落地真实投播能力（此前诊断误判"本地文件无法投播"，官方 Audio Casting 文档证明本地文件经 `AVQueueItem.fdSrc` 即可投）。

### 关键 API 事实（对照官方文档 + Gitee interface_sdk-js avsession.d.ts 核实，本机 SDK 无 avsession.d.ts）
- `AVCastController` 远程控制**仅** `sendControlCommand({command})`（`'play'|'pause'|'stop'|'playNext'|'playPrevious'|'seek'|'setVolume'|...`，seek/setVolume 带 parameter）；**无**直接 pause/play/seek 方法（仅有 prepare/start/release + on/off）。
- `DeviceInfo` **无** `supportedProtocols`；`ProtocolType` **无** `TYPE_DLNA`（仅 LOCAL/CAST_PLUS_MIRROR/CAST_PLUS_STREAM）——旧指南提到的这两处不能用，否则编译失败。
- `AVMediaDescription` 仅 `assetId` 必填；`AVFileDescriptor` 可只给 `{fd}`（同本地播放）。
- 不调用 `castController.release()`（设备断开后系统回收，避免该 method 在部分 SDK 类型缺失导致编译失败）。
