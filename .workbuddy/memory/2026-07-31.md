## 封面改造后 CompileArkTS 再报 4 错（3 error + 1 warn）定点修复

`assembleHap` 在封面改动后报错，全部集中在封面相关两文件：

1. **CoverCache.ets:58** `preload(songs: { src: string }[])` 内联对象字面量作类型 → `arkts-no-obj-literals-as-types`。

2. **PlayerInfoComponent.ets:297-298** `isPixelMap(): value is PixelMap` 用 `is` 类型谓词（`arkts-no-is`）+ `'getImageInfo' in value` 的 `in` 运算符（`arkts-no-in`），ArkTS 均不支持。
   → 删除 `isPixelMap`，改用 `songLabel instanceof image.PixelMap`（`image` from `@kit.ImageKit`，PixelMap 是类，instanceof 合法且可做类型收窄）。Resource 分支仍是 `songLabel as Resource`。
3. **PlayerInfoComponent.ets:267（WARN）** `getMediaContent` 可能抛异常未捕获 → “Function may throw exceptions”。
   → 用 `try/catch` 包裹 `getMediaContent` 调用；为防 ArkTS 确定性赋值告警，`sourcePromise` 给初始值 `Promise.reject(new Error('unreachable'))`。

### ArkTS 可复用红线（沉淀）
- 禁止：内联对象字面量当类型（`{a:string}[]`）→ 用 `interface`；`x is T` 类型谓词；`in` 运算符判属性。
- 调 `throws` 声明 API（如 `resourceManager.getMediaContent`）必须 try/catch 或上层 throws；且 `let` 变量需保证所有路径确定性赋值。
- **⚠️ PixelMap 没有可访问的运行时构造器**：`PixelMap` 只能经 `image.createImageSource(...).createPixelMap()` 工厂创建，故 `instanceof image.PixelMap`（或 `instanceof PixelMap`）在 API 24 **编译失败**——`image.PixelMap` 只是类型、不是 `image` 命名空间上的运行时值（报错 `Property 'PixelMap' does not exist on type 'typeof image'`）。`music.ets` 用 `image.PixelMap` 作类型注解能编译，正是因为它是类型而非值。
- 运行时区分 `Resource | PixelMap` 联合类型 → 用**鸭子类型**而非 `instanceof`/`is`/`in`（三者 ArkTS 均禁）：`private isPixelMap(v: Resource | PixelMap): boolean { return typeof (v as PixelMap).getImageInfo === 'function'; }`。`PixelMap` 有 `getImageInfo` 方法、`Resource`（`$r()` 产物，仅 `id/type/params`）没有 → 稳定区分。函数返回 `boolean`（非谓词），调用处用 `v as PixelMap` / `v as Resource` 显式收窄。
- 改动文件：`CoverCache.ets`、`PlayerInfoComponent.ets`。

## 修复：导入时不读音频元数据（标题/艺术家/专辑/作者），显示「未知艺术家」+ 文件名当标题

### 根因
`LocalLibrary.onPickMusic` 导入歌曲时**从不调用 AVMetadataExtractor**：`song.title` 直接取文件名、`song.singer` 硬编码 `'未知艺术家'`。`CoverCache` 只用 extractor 抽封面，不读文本元数据；`MusicStore` 只持久化 `id/title/singer/src/index`，也不含 album/author/lyric。用户参考的 `01. Lose My Mind (feat. Doja Cat).m4a` 内嵌的标题/艺术家因此从未被读取。

### 改动
1. **新增 `utils/AudioMeta.ets`**：`AudioMetaReader.read(src)` 用 `media.createAVMetadataExtractor()` + `fdSrc={fd,offset:0,length:-1}` + `fetchMetadata()`，返回 `{title,artist,album,author}`；失败静默返回 null；finally 释放 extractor + close fd。
2. **`models/music.ets`**：`SongItem` 增 `album`、`author` 字段。
3. **`LocalLibrary.onPickMusic`**：统一复制/失败两分支为 `srcPath`，导入后 `await AudioMetaReader.read(srcPath)`，填充 `title`(空则回退文件名)、`singer`(空则回退'未知艺术家')、`album`、`author`。
4. **`MusicStore.ets`**：`SongData` 接口增 `album?/author?/lyric?`；`loadState` 两处 map 还原这三个字段；新增**一次性补扫** `refreshMetadataIfNeeded()`（偏好标记 `meta_scanned_v1` 守卫，仅首次启动跑，遍历 songs 读取元数据并回写 singer/title/album/author）。
5. **`EntryAbility.initStore`**：`await store.init()` 后 `await store.refreshMetadataIfNeeded()`，让**已导入**的历史歌曲也在下次启动补上元数据（之后标记跳过，不每次做 I/O）。

### ⚠️ 关键 API 事实（已查 SDK `@ohos.multimedia.media.d.ts` 确认）
- MediaKit `AVMetadata`（`fetchMetadata()` 返回）有 `album/albumArtist/artist/author/composer/dateTime/description/duration/genre/title/trackCount/video*.../customInfo/tracks`，**但完全没有 `lyric` 字段**。

- `AVMetadata` 各字段均为 `?string`（含 `duration` 也是 string，非 number）。
